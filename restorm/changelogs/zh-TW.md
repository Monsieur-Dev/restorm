## v1.2.0

**錄製一個網頁，把它的 API 變成請求。**

- **錄製工作階段。** 一種新的側邊欄項目會在內建迷你瀏覽器中開啟網頁，並即時擷取它發出的每一次 API 呼叫——REST、GraphQL、gRPC-web 與 WebSocket——支援正規表示式白名單與黑名單、在網址列上暫停與停止，執行期間工作階段周圍還有一圈脈動光暈。每個擷取的呼叫都與請求的回應一模一樣地呈現（本文、資訊、Cookie、圖表）；呼叫的右鍵選單可將其 url 加入某個名單，並可選擇清理已擷取的內容。擷取只留在記憶體中，由新的應用程式設定限定上限，絕不會動到您的專案檔。
- **推導路由（Pro）。** 一個按鈕就能把擷取變成一棵由真實、可重播請求組成的資料夾樹：變化的路徑片段變成 `{{param}}` 路徑參數，資料夾沿用靜態前綴，gRPC-web 呼叫依服務歸類，每個請求都依據最後一次成功的呼叫預先填入，並把擷取的呼叫放進其回應歷程。再次推導時會合併——您的修改會被保留。
- **在您的 AI 助理中操控它。** 十個 MCP 工具可建立與設定工作階段、開始與停止錄製、讀取擷取並推導路由。
- **與迷你瀏覽器分享您的位置（選擇性啟用）。** 隱私設定中新增一項，預設關閉，允許在內建瀏覽器中開啟的頁面（無論是否在錄製中）讀取您的大致位置，就像網站本身的定位功能在一般瀏覽器中所做的那樣。開啟時會先徵求您的同意；位置來自系統的定位服務（Linux 上為 GeoClue），若無法取得則改為根據您的 IP 位址所做的城市層級估算。關閉後會立即忘記該位置。
- **更豐富的「回應」分頁。** 圖片現在直接內嵌顯示，影片與音訊可以播放，Markdown 會被轉譯，程式碼編輯器依 Content-Type 選擇語言——並且隨時有一個已翻譯的「下載」按鈕。從歷程中重播的二進位回應不再顯示其 base64。
- **匯入：貼上的 JSON 規格清晰易讀。** 貼到空白匯入欄位的單行 JSON 文件會在編輯器中開啟之前先經過格式化。
- **長清單依然流暢。** 擷取清單（以及超過 400 列的側邊欄）只轉譯畫面上可見的部分。
- 包含錄製工作階段的專案檔以 1.2 格式儲存；較早版本的 Restorm 會請您先更新再開啟這些檔案。

## v1.1.4

**在 macOS 上連接您的 AI 助手——現在穩定可靠。**

- **已修正：macOS 上的 Claude Desktop 和 Cursor。** 連接 AI 助手時能載入 Restorm 的工具，但接著每次呼叫都會失敗並提示「沒有正在執行的執行個體」，即使 Restorm 已開啟也一樣——應用程式與連接器在不同的暫存資料夾裡互相尋找。現在無論連接器由什麼啟動，它們都能穩定地會合。
- **義大利文、波蘭文和芬蘭文的正式措辭。** 介面現在在這三種語言中以正式語氣稱呼您，與其餘部分保持一致。

- **找出匯入 API 中的設計問題。** 匯入 API 後——或重新開啟檔案時——Restorm 會悄悄檢查每個 API 是否存在結構性問題（重複路由、缺少回應、與 Mock Server 衝突的路徑……），在側邊欄以「!」標記它，並新增一個「問題」分頁，列出每個問題以及確切受影響的路由，每條路由都可展開檢視其文件。

## v1.1.1

**API 設計器現在從側邊欄操作。**

- **您的模型、列舉和路由都集中在側邊欄。** 分頁內的三個清單消失了——模型（含其繼承巢狀）、列舉和路由（群組及其路由）現在直接位於側邊欄的樹狀結構中。按右鍵即可重新命名、新增子模型或子群組、複製路由、產生 CRUD 或刪除；拖曳可重新排序或變更父層——絕不會跑到設計之外。每個頁面現在只顯示所選項目的詳細資料。
- **模型、列舉與路由的全域檢視。** 每個區段的根節點現在會列出其下的所有內容——模型還新增了**圖**分頁：一張呈現繼承與參照的類別圖。列舉會把值顯示在名稱旁邊。
- **統一的重新命名入口。** 模型、列舉或路由都從大標題（鉛筆）處重新命名，名稱為空時顯示 **「<未命名>」**，讓鉛筆始終伸手可及——名稱不再於頁面上出現兩次。
- **驗證錯誤指向該項目。** 當出現問題時（模型與列舉同名、參照到已不存在的物件等），該模型、列舉或路由頂端的提示會加以說明。
- **完整的麵包屑。** 路徑會對應側邊欄的完整階層——資料夾 › 設計 › 區段 › 群組 › 項目——每一段都可點擊。
- **多選並一次刪除。** 選取多個模型、列舉或路由，確認後一次刪除。
- **一鍵複製或開啟程式碼範本的來源。** 在「</> Code」頁面，將滑鼠移到範本上會出現一個按鈕用於複製其 URL 或路徑，還有一個用於開啟它——在瀏覽器中開啟儲存庫，或對本機範本開啟磁碟上的資料夾。
- **新路由一開始就有名稱。** 從零建立的路由現在會取得一個預設名稱，因此您可以立即重新命名它。
- **預覽分頁，就像您的編輯器一樣。** 單擊現在會在一個可重複使用的**預覽**分頁中開啟項目（其名稱以斜體顯示）；點擊另一個項目會重複使用同一個分頁，而不是疊加一個新的。對它雙擊、進行任何編輯，或執行一個請求，即可將其永久保持開啟。可在設定 › 行為中關閉。
- **把您要一直開著的分頁釘選住。** 在分頁上按右鍵並釘選它：釘選的分頁始終排在最前，能在「關閉其他」後保留，並按專案記住。
- **環境有了真正的詳細資料檢視。** 開啟一個環境即可從其標題重新命名、設定其圖示與顏色並新增子環境——右鍵選單現在還能連同環境的所有變數與子環境一起複製該環境。

修正：

- **選擇程式碼範本會關閉程式庫。** 「使用」現在會直接把您帶回 Code 頁面。
- **文件產生不再因選填欄位而失敗。** 從模型或參數未設定「required」的設計產生文件，不再因範本錯誤而中斷。
- **刪除列舉會先確認。** 列舉現在與模型和路由一樣會跳出確認。
- **側邊欄會顯示您的選擇。** 開啟「側邊欄與使用中分頁同步」後，選取或建立模型、列舉或路由時會展開其上層，使其在樹狀結構中保持可見。
- **環境按鈕在任何顏色上都保持可讀。** 其文字現在會像執行按鈕一樣切換為深色或淺色，以在環境顏色上保持清晰。
- **中鍵點擊可關閉已開啟的檔案。** 在側邊欄「已開啟」清單中對某項中鍵點擊會關閉其分頁——而且新增的「行為」設定可讓您完全隱藏該面板。
- **從文件開始時用詞更清晰。** 在匯入的 API 文件中，按鈕現在顯示「從此文件建立新請求」。
- **Microsoft Store 版本可以正常登入。** 瀏覽器在您登入後回傳的自訂協定回呼現在已在 Store 套件中宣告，因此登入會順利完成，而不再逾時。

## v1.1.0

🎉 **Restorm 現在也是一款 API 設計器。**設計您的 API，同時橫跨五種協定將它作為即時 mock 提供，並產生它的用戶端——全程不離開應用程式，一切都在您自己的磁碟上。

- **視覺化 API 設計器。**親手為您的 API 建模——模型、列舉（具名或內聯）、路由、參數、具名範例、限制條件、標籤與棄用——無需撰寫一行規格。
- **一鍵將它作為 mock 提供，同時橫跨 5 種協定。**設計會化為一台伺服器，同時以 HTTP、GraphQL、SOAP、OData 和 gRPC 回應。回應來自您的具名範例（或根據您的模型產生的擬真資料），並帶有限制條件驗證、模擬延遲與具狀態模式。
- **開箱即用的用戶端，自動產生。**在 mock 執行期間，Clients 區段會為每個已啟用的協定建立真實、可執行的請求，指向 mock 的端點。一鍵即可開啟一個請求並直擊伺服器——再也不必把您的 API 重新匯入到別處去測試它。
- 使用所提供的範本以及您自己的自訂範本，從您的設計**產生程式碼**，程式碼會在沙箱中算繪，只有在您確認後才寫入磁碟。也可**匯出描述符**（OpenAPI 及其他）。
- **匯入時，請求主體會預先填好**：GraphQL 會選取回傳型別的純量欄位，gRPC 會展開巢狀訊息——請求可原樣執行。

## v1.0.6

修正：

## v1.0.5

**Cookie jar——每個環境各有一罐 Cookie。**

- **每個環境都保留自己的 Cookie。**從兩個環境分別登入您的開發 API 和生產 API，它們的工作階段絕不會互相串門——在一個環境中擷取的 Cookie 只會回傳到那個環境。到期時間、`Path`、`Domain` 及其子網域、`Secure`、`HttpOnly` 和 `SameSite` 如今都會受到遵循，而不再被捨棄。
- **認識 Cookie jar。**全新的工作臺分頁——**檢視 ▸ Cookie jar**——將每個環境的 Cookie 依網域分組，置於可摺疊面板中列出：編輯某個值、刪除某一條、清空某個網域或整罐，也可以手動新增 Cookie。當您的請求設定 Cookie 時，它會即時重新整理。
- **看清每個請求送出與收到了什麼。**現在每個請求在 Response 與 Info 旁邊都多了一個 **Cookies** 分頁，顯示隨該呼叫送出的 Cookie 以及收到的 Cookie——包括在重新導向過程中設定、卻從不會到達最終回應的 Cookie。它在您歷史紀錄中的過往回應上同樣可用。
- **Cookie 登入開箱即用。**傳回 `Set-Cookie` 的請求會被擷取，並在隨後受保護的呼叫中自動重播——在整個情境執行過程中也是如此，其中每一步都共用該環境的 Cookie 罐。
- **Cookie 會像瀏覽器那樣持久保存。**帶有到期時間的 Cookie 會按專案儲存，並在您重新開啟專案時重新載入；工作階段 Cookie 則會在您重新啟動時被捨棄——與瀏覽器的做法別無二致。
- **不僅止於 REST。**GraphQL、SOAP、OData、JSON-RPC、tRPC 和 SSE 現在都能傳送並儲存 Cookie，而 WebSocket 則會在連線交握時攜帶它們。
- **Cookie 可以使用您的變數。**在手動新增的 Cookie 中輸入 `{{token}}`，請求送出時它會依據目前作用中的環境進行解析。

修正：

- **自動儲存現在也涵蓋資料夾內的環境。**在自動儲存模式下，新增或重新命名子環境會立即儲存——對於本就應當寫入磁碟的變更，不再彈出「關閉前是否儲存？」的提示。

## v1.0.0

**Restorm 1.0 —— 本地優先的 API 用戶端，正式發布。**

Restorm 是一款快速、離線優先的桌面用戶端，可在所有主流協定上測試並驅動 API。
